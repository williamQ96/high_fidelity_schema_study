# Project Abstract

Last updated: 2026-06-24

High-Fidelity Schema Study is a deterministic-first framework for extracting auditable, high-trust schemas from heterogeneous scientific data files. Its core objective is intentionally narrow and strict: take an input resource, such as CSV, HDF5, NetCDF/CF, Zarr, Parquet/Arrow, JSON, XML, time-series organization, or opaque binary, and produce the strongest schema that is justified by file structure, explicit metadata, deterministic validation, and recorded evidence. When the file does not contain enough reliable signals, the correct output is not a plausible guess; it is a structured unknown, conflict, partial result, failure, or abstention.

The project is motivated by a practical gap in scientific data reuse. Research data often arrives as a mixture of tabular files, hierarchical binary containers, array stores, nested documents, time axes, sidecar descriptions, and repository metadata. Existing workflows can expose fragments of this structure, but they often collapse very different claim types into one schema-like object: directly observed physical fields, derived logical roles, semantic labels, inferred units, and unsupported guesses. This framework instead treats schema extraction as an evidence management problem. Physical structure, logical interpretation, semantic meaning, provenance, and uncertainty are kept separate so that downstream users and future agents can inspect not only what the schema says, but why each claim exists.

The central extraction path is registry-backed and conservative. A shared intake layer detects format signals through trusted signatures, compatible hints, supported suffixes, and bounded text probes. It then routes the file through an extractor capability registry or returns a structured abstention when no spec-backed extractor is available. Registered extractors currently cover CSV, HDF5, NetCDF/CF, Zarr v2 local directory stores, Parquet/Arrow, JSON/JSON Lines, and XML/XSD, with deliberate raw-binary abstention for unsupported opaque payloads. Each outcome records the format decision, extractor identity when applicable, schema payload when available, and typed issues such as dependency failures, parser failures, unsupported features, partial extraction, ambiguity, or conflicting format signals.

Schema outputs are layered. The physical layer records fields, paths, groups, variables, dimensions, dtypes, shapes, nullability, missing markers, attributes, file-level structure, and format-specific metadata. The logical and semantic layers represent roles such as identifiers, coordinates, time axes, measurements, units, standard names, and descriptions only when supported by deterministic rules or explicit evidence. Temporal semantics are handled by a dedicated subsystem that preserves timezone information, distinguishes UTC, explicit offsets, naive timestamps, mixed offsets, regularity, frequency, missing intervals, split date parts, and ambiguous competing time candidates. The unified schema envelope projects these results into a versioned cross-format shape while preserving legacy schema outputs.

A key design principle is that semantic interpretation cannot create physical fields. LLM-assisted annotation appears only in older constrained experimental tracks and remains downstream of deterministic structure. Future bounded agents may inspect evidence, request reruns, or propose noncanonical annotations, but they must not replace parsers, mutate canonical claims, or promote weak evidence into truth. This makes the system best understood as an agent-ready deterministic schema substrate rather than an autonomous data agent.

The repository includes a frozen Artifact Paper slice and a sequence of post-freeze engineering phases. The frozen slice evaluates deterministic extraction, evidence adequacy, semantic merge behavior, and controlled retrieval over a compact internal pilot corpus plus an external retrieval pool. Post-freeze Phases 12 through 20 extend the substrate with a central orchestration API, structured failures and abstentions, temporal validators, additional registered formats, a unified envelope, categorized evaluation, read-only agent exports, GUI scratch extraction, runnable demo examples, pinned dependencies, and CI. These later phases are versioned separately and do not rewrite the frozen benchmark, gold references, paper tables, figures, manuscript, or headline metrics.

The current release-style state is demo-ready within bounded claims. The full regression suite passes with pinned dependencies, the release audit reports ready, GitHub Actions covers Ubuntu and Windows, generated experiment artifacts avoid local absolute paths, and frozen artifact paths remain unchanged. The project does not claim broad real-world robustness from its controlled challenge packs. The recommended next step is broader external and multi-producer compatibility validation for supported formats, followed by carefully scoped future extensions such as additional scientific containers or bounded agent integrations built on the existing registry, evidence, and abstention contracts.
